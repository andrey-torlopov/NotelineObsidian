# Даты, теги и серые рамки

[English](../en/dates-and-tags.md) · **Русский** · [Документация](index.md)

## Источники и форматы даты

Начальный приоритет: первое непустое свойство `timeline-date`, затем `date`, затем начальная строка `📅`. Имена и порядок меняются через **Параметры даты** или настройки плагина. Регистр имен учитывается.

| Источник | Допустимый пример |
| --- | --- |
| Свойство или начальная строка | `2026-10-22` |
| Свойство или начальная строка | `2026-10-22 15:30` |
| Только свойство | `2026-10-22T15:30` |
| Только свойство | `2026-10-22T15:30:00` |

Храните даты свойств строками; кавычки в YAML делают это явным. Дата без времени имеет точность до дня, выдуманное `00:00` не показывается. Это григорианские календарные даты в диапазоне `0001–9999`, не зависящие от часового пояса устройства. UTC `Z`, смещения, дробные или ненулевые секунды, несуществующие дни и неоднозначные локальные форматы не принимаются.

Начальный блок идет после необязательного YAML frontmatter. В нем допустимы пустые строки, `📅`, `📍 Tags:`, `🧭 MOC:` и `🔗 Links:`. Маркер даты должен начинаться с начала строки. Разбор останавливается на обычном тексте, заголовке, разделителе, блоке кода или после первых 32 строк за frontmatter. Дата из середины текста не становится датой события.

Заполненный, но неверный источник с наивысшим приоритетом вызывает ошибку без молчаливой подстановки. Корректная дата более приоритетного источника используется при конфликте с нижележащими, с предупреждением. Повторные маркеры даты и поврежденный YAML диагностируются отдельно. Время создания/изменения файла и имя файла не считаются датой события.

## Отсутствующие поля

| Дата в заметке | Теги в заметке | Дата карточки | Рамка |
| --- | --- | --- | --- |
| Есть | Есть | Из заметки | Обычная |
| Нет | Есть | Сохраненная локальная дата добавления | Серая: нет даты |
| Есть | Нет | Из заметки | Серая: нет тегов |
| Нет | Нет | Сохраненная локальная дата добавления | Серая: обе причины |

Пустое свойство, пустой список `tags` и пустая `📍 Tags:` не означают заполненное поле. Подставленная дата хранится в данных плагина, а не дописывается в заметку. Она остается прежней после перезапуска, смены дня и часового пояса.

Реальная дата в источнике перемещает карточку и очищает сохраненную подстановку. Если дату потом удалить, новая подстановка фиксируется в день обнаружения отсутствия. Удаление карточки и повторное добавление также создают новую подстановку, если заметка по-прежнему без даты.

Серая рамка исчезает только после заполнения обоих полей в заметке. Одни теги не устраняют отсутствие даты. Ошибка чтения и еще не готовые метаданные не считаются отсутствующей датой.

## Чтение и добавление тегов

Объединяются YAML `tags`, inline-теги Obsidian и начальная строка `📍 Tags:`. Дубликаты сравниваются без регистра; сохраняется первое написание. Валидатор записи принимает буквы, комбинируемые знаки, цифры, подчеркивание, дефис и вложенные сегменты через `/`. Тег не может содержать пробелы или состоять только из числа. Теги из одних emoji валидатор этой версии не поддерживает.

**Добавить тег** записывает один явный тег. Повтор уже существующего тега ничего не дописывает. Место записи:

1. Существующая однозначная начальная строка `📍 Tags:`.
2. Иначе — существующее корректное свойство YAML `tags`.
3. Иначе — новая начальная строка `📍 Tags:` после даты либо после frontmatter и начальных пустых строк.

Несколько строк тегов или невалидное место назначения блокируют запись с объяснением. Текст меняется по текущему буферу редактора или транзакцией по актуальному файлу. Изменение YAML сохраняет тело и значения прочих свойств, но может изменить форматирование YAML. Если заметка с YAML-тегами открыта в исходном редакторе, измените теги через Properties или закройте редактор перед повтором.

Действие не удаляет теги, не меняет дату и не переписывает произвольные хештеги в тексте. [Данные и резервные копии](data-and-security.md).
