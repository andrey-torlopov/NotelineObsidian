# Разработка и публикация

[English](../en/development.md) · **Русский** · [Документация](index.md)

## Сборка исходников

Нужны Node.js 24+ и npm. Клонируйте репозиторий и выполните в его корне:

```sh
npm ci
npm run check
npm run build
```

`check` проверяет манифесты, запускает ESLint, проверяет TypeScript без генерации файлов и выполняет автоматические тесты. `build` создаёт минифицированный CommonJS-файл `main.js` для ES2020 с внешней зависимостью Obsidian. `npm run dev` запускает наблюдение esbuild за исходниками. `main.js` и `node_modules` не включаются в коммиты исходного кода.

Установите `main.js`, `manifest.json` и `styles.css` в `plugins/noteline/` тестового хранилища. [Установка](installation.md). Отдельно проверяйте настоящий Obsidian: модульные тесты не подтверждают нативное отображение или работу на физическом устройстве.

## Структура исходников

| Путь | Назначение |
| --- | --- |
| `src/main.ts` | Жизненный цикл, интеграция с хранилищем, команды и настройки |
| `src/domain/` | Календарные метаданные, геометрия оси и проверка сохранённого состояния |
| `src/services/` | Запись заметок и последовательное сохранение |
| `src/ui/` | Представление оси, диалоги и карточки |
| `tests/` | Регрессионные проверки предметной логики и сервисов |
| `scripts/validate-manifest.mjs` | Согласованность метаданных и проверка desktop-импортов |
| `styles.css` | Изолированные стили с переменными Obsidian |

## Манифест и файлы релиза

Корневой [`manifest.json`](../../manifest.json) описывает плагин. Согласуйте следующие значения:

| Поле | Текущее значение / смысл |
| --- | --- |
| `id` | `noteline`; также имя каталога установки |
| `name` | `Noteline` |
| `version` | `0.2.0`; формат `x.y.z`, совпадает с тегом релиза |
| `minAppVersion` | `1.7.2`; минимальная заявленная версия Obsidian |
| `isDesktopOnly` | `false`; мобильная установка разрешена, проверка физических устройств ещё предстоит |
| `author`, `authorUrl` | Автор и ссылка на профиль |
| `description` | Краткое английское описание фактических возможностей |

В `package.json` и `package-lock.json` должна стоять та же версия плагина. [`versions.json`](../../versions.json) связывает каждую опубликованную версию с минимальной поддерживаемой версией Obsidian.

Для выпуска выполните проверки и production-сборку из выбранного коммита. Опубликуйте **GitHub Release** с тегом, в точности равным `manifest.version`: **`0.2.0`, без `v`**. Приложите отдельными файлами `main.js`, `manifest.json` и `styles.css` с этими точными именами. Одного тега, черновика релиза или архива исходников недостаточно для установки. Сверьте скачанные файлы с подготовленными.

Ошибка **No release matches your manifest version** означает, что Community не находит опубликованный релиз для манифеста основной ветки. До изменения корректного манифеста проверьте точный тег, состояние публикации и вложения. Для следующих изменений кода увеличивайте версию и выпускайте соответствующий релиз: замена уже распространяемой версии может оставить у пользователей разные файлы с одним номером.

## Подача в Community

Следуйте актуальному руководству Obsidian [Submit your plugin](https://docs.obsidian.md/Plugins/Releasing/Submit%20your%20plugin). В основной ветке нужны корректные манифест, README и лицензия; для распространения через каталог нужен соответствующий опубликованный релиз. Подача и одобрение Community — отдельные действия после GitHub Release. Репозиторий не заявляет об одобрении Community.

Перед публикацией проверьте в тестовом хранилище подставленные даты и серые рамки, явную запись тегов, резервное копирование и перезапуск, перепривязку потерянных заметок и заявленные платформы. Не называйте мобильную совместимость проверенной без испытания на устройстве.
