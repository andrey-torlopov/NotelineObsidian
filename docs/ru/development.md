# Разработка и публикация

[English](../en/development.md) · **Русский** · [Документация](index.md)

## Сборка исходников

Для 0.4.1 нужны Node.js 24+ и npm. Клонируйте репозиторий и выполните в его корне:

```sh
npm ci
npm run check
npm run build
```

`check` проверяет манифесты, запускает ESLint, проверяет TypeScript без генерации файлов и выполняет автоматические тесты. `build` создаёт минифицированный CommonJS-файл `main.js` для ES2020 с внешней зависимостью Obsidian. `npm run dev` запускает наблюдение esbuild за исходниками. `main.js` и `node_modules` не включаются в коммиты исходного кода.

`npm test` запускает штатный тестовый runner Node для `tests/*.test.mjs`; тесты напрямую импортируют TypeScript с удаляемой аннотацией типов. Контролируемые адаптеры Obsidian проверяют сервисы без запуска приложения. Они не заменяют реальный редактор, рендерер, синхронизацию и файловый жизненный цикл.

Установите `main.js`, `manifest.json` и `styles.css` в `plugins/noteline/` тестового хранилища. [Установка](installation.md). Отдельно проверяйте настоящий Obsidian: модульные тесты не подтверждают нативное отображение или работу на физическом устройстве.

## Структура исходников

| Путь | Назначение |
| --- | --- |
| `src/main.ts` | Регистрация расширения, владение сессиями осей, миграция, события хранилища и команды |
| `src/domain/` | Календарные метаданные, геометрия оси и проверка сохранённого состояния |
| `src/services/timeline-session.ts` | Контроллер заметок отдельного файла, чтение метаданных, подставленные даты и защита от устаревших запросов |
| `src/services/timeline-files.ts` | Чтение, валидация и создание JSON `.timeline`, сравнение файла перед сохранением |
| `src/services/persistence.ts` | Последовательные снимки, повтор сохранения и конфликты внешних изменений |
| `src/services/notes.ts` | Явная запись тегов через актуальный буфер или транзакцию |
| `src/ui/` | `EditableFileView` для `.timeline`, диалоги файлов, ориентация/направление и карточки |
| `tests/` | Регрессионные проверки предметной логики и сервисов |
| `scripts/validate-manifest.mjs` | Согласованность метаданных и проверка desktop-импортов |
| `styles.css` | Изолированные стили с переменными Obsidian |

Код использует [публичные объявления API Obsidian](https://github.com/obsidianmd/obsidian-api/blob/master/obsidian.d.ts), включая `EditableFileView`, `registerExtensions`, `Vault.process`, `FileManager.processFrontMatter` и `MarkdownRenderer.render`. Файловые Node/Electron API не нужны. [Контракт файла оси](timeline-files.md) описывает схему `1`; `data.json` плагина содержит навигацию и сведения о миграции, а не активный документ оси.

## Манифест и файлы релиза

Корневой [`manifest.json`](../../manifest.json) описывает плагин. Согласуйте следующие значения:

| Поле | Текущее значение / смысл |
| --- | --- |
| `id` | `noteline`; также имя каталога установки |
| `name` | `Noteline` |
| `version` | `0.4.1`; формат `x.y.z`, совпадает с тегом релиза |
| `minAppVersion` | `1.7.2`; минимальная заявленная версия Obsidian |
| `isDesktopOnly` | `false`; мобильная установка разрешена, проверка физических устройств ещё предстоит |
| `author`, `authorUrl` | Автор и ссылка на профиль |
| `description` | Краткое английское описание фактических возможностей |

В `package.json` и `package-lock.json` должна стоять та же версия плагина. [`versions.json`](../../versions.json) связывает каждую опубликованную версию с минимальной поддерживаемой версией Obsidian.

Подготовьте проверенную production-сборку выбранного коммита. Для 0.4.1 тег опубликованного релиза должен быть **`0.4.1`, без `v`**. Приложите `main.js`, `manifest.json` и `styles.css` отдельно и сверьте скачанные файлы. Архива исходников или черновика релиза недостаточно.

При ошибке **No release matches your manifest version** проверьте манифест основной ветки, точный опубликованный тег и вложения до изменения корректных метаданных. Для следующих изменений кода увеличивайте версию.

## Подача в Community

Следуйте [руководству Obsidian по подаче](https://docs.obsidian.md/Plugins/Releasing/Submit%20your%20plugin): нужны корректные манифест, README, лицензия и соответствующий опубликованный релиз. Одобрение Community — отдельный этап; репозиторий не заявляет об одобрении.

Перед публикацией следующей сборки повторяйте проверки независимых файлов/вкладок, обеих ориентаций и направлений, дат до нашей эры и неполных дат, серых рамок, записи тегов, миграции, копирования/перечитывания, устаревшей записи и перепривязки в тестовом хранилище.

Версия 0.3.0 прошла базовый прогон в Obsidian 1.14.4 на macOS: включение; перенос трёх старых записей с раскрытием и подставленными датами; две независимые файловые оси; создание/копирование/добавление/удаление с сохранением исходной заметки; обе ориентации и обратные направления; обзор всех дат; точность до месяца, года, римского века, года и века до нашей эры; сохранение после перезагрузки приложения; внешнее изменение сохранённого файла с применением ориентации, направления и раскрытия.

Физические iOS/Android, Windows/Linux, сама Obsidian 1.7.2, сенсорные жесты и фактический перенос/конфликты средств синхронизации ещё не проверены. Проверка локального обновления файла не подтверждает поведение средства синхронизации.

Изменение жестов 0.4.0 — итерация со статическим анализом и автоматическими регрессиями событий. Новый результат проверки на физическом устройстве или в настоящем Obsidian для этой сборки не заявляется. После обновления подтвердите [сенсорные сценарии](quick-start.md#сенсорные-устройства) на реальном iPhone/iPad; [анализ](../ios-scroll-analysis.md).
