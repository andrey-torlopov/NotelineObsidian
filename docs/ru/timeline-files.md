# Файлы осей и независимые вкладки

[English](../en/timeline-files.md) · **Русский** · [Документация](index.md)

## Создание, открытие и управление

В 0.3.0 каждая ось — JSON-файл с расширением `.timeline` внутри хранилища. Выполните **Noteline: Создать временную ось** или нажмите **Создать ось** на панели и задайте путь относительно хранилища. Если расширение не указано, оно добавится. Существующие файлы не перезаписываются.

Откройте файл из хранилища, выполните **Noteline: Выбрать временную ось** или используйте список **Выбрать временную ось** на панели. Разные файлы открываются в отдельных вкладках. У каждого файла свои состав заметок, приоритет свойств даты, подставленные даты, раскладка, раскрытие, область просмотра, ориентация и направление времени. Одна заметка может участвовать в нескольких файлах. Вкладки одного файла относятся к одному документу.

| Действие на панели | Результат |
| --- | --- |
| **Сохранить копию оси** | Новый файл из текущего расположения в памяти, включая несохранённые изменения; тексты заметок не копируются |
| **Перечитать файл оси** | После подтверждения заменить расположение в памяти версией файла; при необходимости сначала сохраните копию |
| **Удалить ось** | После подтверждения отправить файл оси в настроенную корзину; исходные заметки остаются |
| **Ориентация оси / Направление дат** | Сохранить горизонтальное/вертикальное отображение и прямой/обратный порядок в этом файле |

Удаление карточки меняет только её участие в этой оси. Добавление тега меняет общую исходную заметку и видно на других осях с этой заметкой. [Управление](quick-start.md).

## Минимальный полный пример

Создайте заметку `Notes/Research kickoff.md`:

```markdown
---
date: "2026-10-23"
tags:
  - research
---

# Начало исследования

Здесь начинается исследовательский дневник.
```

Следующий полный документ `Research.timeline` включает эту заметку:

```json
{
  "schemaVersion": 1,
  "settings": {
    "dateProperties": ["timeline-date", "date"]
  },
  "timeline": {
    "entries": [
      {
        "entryId": "research-kickoff",
        "filePath": "Notes/Research kickoff.md",
        "preferredLane": 0,
        "expanded": false
      }
    ]
  }
}
```

Для обычного редактирования используйте интерфейс. Перед внешним просмотром или изменением JSON сохраните резервную копию и завершите либо закройте активное редактирование.

## Контракт файла

Обязательны `schemaVersion: 1`, `settings.dateProperties` и `timeline.entries`. Имена свойств даты — уникальные непустые строки в порядке приоритета; пустой список оставляет источником начальный маркер `📅`. В записи обязательны уникальный непустой `entryId`, уникальный путь `.md` относительно хранилища в `filePath`, целый неотрицательный `preferredLane` и логическое значение `expanded`. Абсолютные пути, обратные слеши и сегменты `.`/`..` не принимаются.

Необязательные поля:

- `entry.fallbackDate`: существующий день `YYYY-MM-DD`, сохранённый для заметки без исходной даты. Невалидную дату он не заменяет. Неполные даты и даты до нашей эры остаются в заметке.
- `timeline.orientation`: `"horizontal"` или `"vertical"`; при отсутствии используется горизонтальное отображение.
- `timeline.reverse`: логическое значение; при отсутствии время идёт от старых дат к новым.
- `timeline.viewport`: числовые календарные координаты `start` и `end` в миллисекундах с диапазоном не меньше часа; обязателен неотрицательный `scrollTop`, необязателен неотрицательный `scrollLeft`. Область просмотра должна оставаться внутри поддержанного календарного диапазона.

Совместимые неизвестные поля сохраняются. Повреждённый JSON, неподдерживаемая версия схемы и неверные известные поля вызывают сообщение без сброса исходного файла.

## Миграция и синхронизация

Старое состояние единственной оси из `data.json` переносится в `Noteline.timeline` либо под другое свободное имя. Прежние поля остаются в данных плагина для восстановления; `notelineFiles.migratedPath` и `lastPath` фиксируют перенос и навигацию. После миграции общим источником состояния осей становятся `.timeline`-файлы.

Синхронизируйте их вместе с заметками и вложениями. При сохранении актуальный локальный файл сравнивается с ранее загруженной версией; устаревшая перезапись блокируется. Это не объединяет раскладки и не запрещает средству синхронизации заменить файл позднее. При конфликте сохраните копию перед подтверждённым перечитыванием. [Резервные копии, настройки Sync desktop/iOS и восстановление](data-and-security.md).
