# Данные, приватность, копирование и синхронизация

[English](../en/data-and-security.md) · **Русский** · [Документация](index.md)

## Что сохраняется

Версия 0.4.0 сохраняет каждую ось отдельным JSON-файлом с расширением `.timeline` внутри хранилища, например `Исследования/История семьи.timeline`. Разные файлы можно открывать в отдельных вкладках.

| Файл | За что отвечает |
| --- | --- |
| Markdown-заметки и вложения | Исходный текст, даты, теги и медиа |
| Каждый `.timeline`-файл | Версия схемы `1`, настройки свойств даты, пути заметок и ID записей, уровни раскладки, раскрытие, подставленные даты, область просмотра, ориентация и направление времени |
| `plugins/noteline/data.json` в каталоге конфигурации хранилища | Последний открытый путь и сведения о миграции в `notelineFiles`; прежние поля после миграции |

`.timeline`-файл — общий источник состояния конкретной оси. В нём хранятся пути относительно хранилища, а не тексты заметок или вложения. У каждого файла независимые состав заметок, настройки дат, подставленные даты и раскладка. Одна заметка может участвовать в нескольких осях без дублирования. Копирование оси копирует ссылки и настройки, а не заметки.

Добавление заметки, размещение и раскрытие карточки, удаление карточки меняют файл этой оси. Исходная заметка не переписывается и не удаляется. **Явное добавление тега записывает его в исходную заметку**, поэтому изменение видно и на других осях с этой заметкой. При записи YAML форматирование может измениться; значения других свойств и тело сохраняются. [Правила записи тегов](dates-and-tags.md).

## Перенос из версий с одной осью

При первом запуске корректное старое состояние из `data.json` переносится в `Noteline.timeline`. Если имя занято другими данными, используется свободное, например `Noteline 2.timeline`. Уже существующий эквивалентный файл переноса может быть использован повторно. Исходные поля остаются в `data.json` для восстановления; `notelineFiles.migratedPath` хранит путь переноса, `lastPath` — навигацию.

После переноса источником состояния становится `.timeline`-файл. Старые поля не являются второй активно синхронизируемой осью. Невалидные старые данные сохраняются с сообщением об ошибке, а не заменяются пустым файлом. При обновлении сохраняйте `data.json`, чтобы не потерять сведения о миграции и прежние данные.

## Сеть и внешнее содержимое

Noteline не выполняет собственных сетевых запросов и не содержит телеметрии, учётной записи или подключения к серверу. Markdown отображает Obsidian. Изображения, встраивания, ссылки и другие плагины могут обращаться к внешним ресурсам; временная ось не фильтрует сетевое содержимое.

## Резервная копия и восстановление

1. Дождитесь статуса **Сохранено** на изменённых осях. Перед разрешением конфликта сохраните копию несохранённой оси.
2. Закройте Obsidian на устройствах с этим хранилищем и приостановите синхронизацию перед копированием или восстановлением.
3. Скопируйте всё хранилище: `.timeline`-файлы, заметки, вложения и скрытый каталог конфигурации с `plugins/noteline/data.json`.
4. Для восстановления сначала сохраните копию текущих файлов, восстановите соответствующие друг другу оси и исходные файлы, затем откройте Obsidian. Проверьте пути, состав осей, подставленные даты, раскладку и ориентацию.

Noteline не ведёт автоматическую историю резервных копий. Сохранение прежних данных при миграции не заменяет регулярное копирование. Действие сохранения копии на панели создаёт другой снимок оси с теми же ссылками на заметки. Одни файлы осей не восстановят удалённые заметки; одни заметки не восстановят состав и раскладку осей.

Удаление `data.json` в 0.4.0 не удаляет существующие `.timeline`-файлы, но стирает навигационные настройки и сохранённые старые данные для восстановления. Удаление `.timeline`-файла удаляет эту ось, а не исходные заметки. Панель запрашивает подтверждение и отправляет файл в настроенную корзину Obsidian. Не удаляйте эти файлы как штатный способ исправления ошибок.

## Несколько устройств

Синхронизируйте `.timeline`-файлы вместе с заметками и вложениями, сохраняя одинаковые пути относительно хранилища. Одной синхронизации установки или настроек плагина недостаточно. В Obsidian Sync на каждом устройстве включите **Settings → Sync → Selective sync → Sync all other types** — синхронизацию остальных типов файлов. Настройки Sync индивидуальны для устройства; после изменения выборочной синхронизации перезапустите приложение, при необходимости принудительно завершив его на мобильном устройстве. [Официальные настройки Sync](https://obsidian.md/help/sync/settings).

Для файлов, отличных от Markdown, Obsidian описывает правило «побеждает последнее изменение». `.timeline` — собственный тип файла, поэтому не следует ожидать слияния, применяемого к заметкам или JSON-настройкам плагинов. Другие средства синхронизации также могут заменять прежние версии. Меняйте одну ось на одном устройстве за раз и дожидайтесь завершения синхронизации. [Официальные правила конфликтов](https://obsidian.md/help/sync/troubleshoot).

Перед сохранением Noteline проверяет актуальный текст файла оси. Если он отличается от версии, загруженной вкладкой, устаревшая запись блокируется. Эта локальная проверка не запрещает средству синхронизации заменить файл позднее. Внешнее изменение можно автоматически перечитать, когда локальные данные сохранены; несохранённые изменения вызывают конфликт. Сохраните их отдельной копией через панель, затем перечитайте файл и подтвердите замену расположения в памяти. Плагин не объединяет две раскладки автоматически.

### Desktop и iOS

**Заметки появились, а ось — нет.** Проверьте наличие `.timeline`-файла на втором устройстве, исключения его папки и включение нестандартного типа файлов в синхронизацию именно на этом устройстве. Установите ту же совместимую версию Noteline и откройте файл через выбор оси.

**Ось открывается, но заметки потеряны.** Пути заметок заданы относительно хранилища. Дождитесь появления заметок и вложений по тем же путям; одного копирования файла оси недостаточно.

**Объединятся ли изменения с desktop и iOS?** Совместного слияния нет. Дожидайтесь синхронизации и переходите между устройствами последовательно; при конфликте сохраняйте отдельные копии. На macOS в Obsidian 1.14.4 внешнее изменение сохранённого `.timeline`-файла применило ориентацию, направление и состояния раскрытия. Фактический перенос/конфликты средств синхронизации и физические iOS/Android ещё не проверены.

Повреждённая или неподдерживаемая схема включает режим чтения, исходный файл не перезаписывается. Сохраните его и восстановите исправную копию либо используйте совместимую версию плагина. [Диагностика](troubleshooting.md).
