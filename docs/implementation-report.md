# Реализация Noteline V1

Дата: 2026-10-22. Репозиторий: `andrey-torlopov/noteline`. Версия метаданных: `0.1.0`.

Исходники плагина созданы по плану V1 с уточнением об отсутствующих дате и тегах. Ни публикация, ни установка в рабочее хранилище не выполнялись.

## Реализовано

| Требование | Реализация |
| --- | --- |
| R01: существующие заметки | Состав оси хранит ID и относительные пути; заметки не копируются; удаление карточки не удаляет файл |
| R02: дата | Строгий календарный parser, настраиваемый порядок свойств, начальный блок 📅, конфликты и ошибки; при отсутствии даты сохраняется текущая дата добавления |
| R03: ручная высота | Уровни с разрешением коллизий, Pointer Events, клавиатура и кнопки выше/ниже; пустые уровни сохраняют видимую высоту даже для одной карточки |
| R04: масштаб | Масштаб относительно указателя, минимальное окно один час, верхний предел по данным и обзорному окну, календарные деления, переход к дате, fit и pan |
| R05: состояния | Сворачивание и ленивый штатный Markdown-render только для видимых раскрытых карточек; отдельные компоненты и контейнеры на поколение рендера |
| R06: видимая дата | Дата видна в обоих состояниях; время только из источника; подстановка явно помечена |
| R07: теги | Стандартные/inline/📍 Tags:, объединение без дубликатов, безопасное явное добавление через Editor, Vault.process или processFrontMatter |
| R08: весь vault | Выбор по имени и полному пути доступных Markdown-файлов; команда активной заметки и меню файла; потерянную связь можно перепривязать |
| R09: темы | Scoped CSS с variables Obsidian, серый контур с текстовой причиной, видимый фокус, responsive toolbar и сенсорные кнопки |

Признаки отсутствия даты и тегов независимы. Если нет только тегов, исходная дата не заменяется. `fallbackDate` хранится в состоянии плагина и не смещается после перезапуска или смены дня. После заполнения полей признаки дефекта снимаются. При добавлении карточки Markdown не переписывается.

## Структура

- `src/domain/`: parser, правила изменения метаданных, календарная шкала, раскладка и схема состояния.
- `src/services/`: адресная запись тегов и последовательная очередь сохранения, включая последнее изменение при выгрузке.
- `src/main.ts`: регистрация плагина, файловые события, ограниченная очередь чтения и защита от устаревших результатов.
- `src/ui/`: вкладка, карточки, модальные формы, Pointer Events и клавиатура.
- `styles.css`: темы, адаптация ширины и состояния карточек.
- `tests/`: native Node.js tests чистой логики, транзакций и контроллера с изолированными адаптерами Obsidian.

Тестовый runner — встроенный в Node.js 24, вместо предложенного в плане Vitest. Это уменьшает число инструментов и не требует предварительной сборки тестируемых TypeScript-модулей.

## Манифесты и Community

`manifest.json`, `versions.json` и `package.json` согласованы: `noteline`, `Noteline`, `0.1.0`, Obsidian `1.7.2`. `isDesktopOnly: false`: runtime использует публичные API Obsidian и браузера, без Node.js, Electron, собственного сервера или телеметрии. README описывает возможные внешние загрузки штатного Markdown-renderer.

Структура сверена с манифестами TraceWeaveObsidian, идентификация/версия/платформы заданы отдельно для Noteline. Валидатор проверяет типы полей, версии, лицензию, README и прямые desktop-импорты. Уникальность ID/имени проверена по доступному официальному реестру при подготовке; перед подачей проверить повторно.

- [Официальная схема manifest](https://docs.obsidian.md/Reference/Manifest).
- [Текущая инструкция подачи](https://docs.obsidian.md/Plugins/Releasing/Submit%20your%20plugin).
- [Манифест образца TraceWeave](https://github.com/andrey-torlopov/TraceWeaveObsidian/blob/main/manifest.json).

Минимальная версия выбрана по контрактам используемых API, включая deferred views и `revealLeaf`. Запуск на реальном Obsidian 1.7.2 еще не проверен.

Покрыты невалидные/конфликтующие даты, разные часовые пояса, годы 0001–0099, все сочетания отсутствующих полей, BOM/CRLF, комментарии и ссылки вместо тегов, параллельные изменения текста/YAML, открытый буфер редактора, очередь сохранения и ее ошибки, перезапуск с подставленной датой, rename/relink/remove и устаревшие чтения, поздняя отправка формы, геометрия и финальная позиция переноса до RAF.

Тестовые адаптеры подтверждают поведение собственного кода. Они не заменяют проверки API в установленном Obsidian и реального Markdown-renderer.

## Проверка в реальном Obsidian

Проверено в Obsidian 1.14.4 на macOS. Создан отдельный временный vault `/var/folders/82/x6611z5125b8nw864tynf8dh0000gn/T/noteline-smoke-yi8ovsqy` с четырьмя синтетическими заметками и копией собранного плагина. В рабочее хранилище пользователя плагин не устанавливался.

Через интерфейс подтверждены:

- Успешная загрузка плагина, регистрация команд/кнопки и открытие оси.
- Markdown в развернутой карточке: заголовок, выделение, wikilink, список, callout; сворачивание обратно.
- Обычная карточка с полной датой и тегами; карточки с отсутствующей датой, отсутствующими тегами и обоими полями. В последних случаях видны серый контур и соответствующие подписи.
- Подстановка `2026-10-22` в обе заметки без даты и сохранение `fallbackDate` в `data.json` без изменения этих Markdown-файлов.
- Добавление `#проверка` из карточки в строку `📍 Tags:` заметки `02 Missing tags.md`: исходная дата и остальной текст сохранены, причина «Нет тегов» исчезла, рамка вернулась к обычному оформлению.
- Переключение светлой/темной темы в тестовом vault без переоткрытия вкладки; тексты, контуры, кнопки и ось читаемы.
- «Показать все», увеличение масштаба и подъем карточки кнопкой; закрытие и новое открытие вкладки сохранили масштаб, высоту и свернутое состояние.

Постоянное состояние и точное содержимое измененной тестовой заметки дополнительно проверены чтением файлов. Проверка вкладки не является полным перезапуском приложения. CLI Obsidian не смог подключиться к приложению; проверка проведена через UI.
