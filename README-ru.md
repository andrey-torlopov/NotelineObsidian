# Noteline для Obsidian

[English](README.md) · **Русский**

## Зачем нужен Noteline

Проект, исследовательский дневник или коллекцию идей часто удобнее читать в хронологическом порядке. Noteline размещает существующие заметки Obsidian на горизонтальной временной оси: видно, когда произошло событие, а текст можно прочитать прямо в карточке.

Выбирайте заметки из любых папок, раскрывайте Markdown и меняйте высоту карточек, сохраняя их даты. Заметки остаются обычными файлами на своих местах. Состав оси, раскладка и область просмотра сохраняются отдельно.

Баннер — оригинальная иллюстрация, а не скриншот плагина.

**Документация доступна на русском и английском. Интерфейс версии 0.2.0 — русский.** Английские руководства содержат реальные русские названия элементов. Перевод документации не добавляет переключатель языка интерфейса.

## Возможности

- Добавление существующих Markdown-заметок из всего хранилища, включая разные папки с одинаковыми именами файлов.
- Даты из свойств заметки или начальной строки `📅`, с необязательным временем.
- Свернутые карточки с названием, датой и тегами; раскрытие для чтения штатного Markdown Obsidian.
- Перемещение карточек выше и ниже; положение по горизонтали определяется датой.
- Масштабирование, сдвиг оси, обзор выбранных заметок и переход к дате или сегодняшнему дню.
- Серый контур и текстовая причина, если у заметки отсутствуют дата или теги.
- Явное добавление тега в исходную заметку; добавление и перемещение карточки текст не переписывают.
- Сохранение оси между сеансами, светлая и темная темы, кнопки для сенсорных экранов.
- Тонкая временная ось с кольцевыми точками заметок, тонкие рамки карточек, округлые теги и мягкий градиентный фон по мотивам баннера.

Если даты нет, Noteline подставляет локальную дату добавления и сохраняет ее. Карточка остается на этом дне, а не перемещается вслед за «сегодня». Если отсутствуют только теги, исходная дата сохраняется. [Правила дат и тегов](docs/ru/dates-and-tags.md).

## Быстрый старт

**Obsidian 1.7.2 или новее.** Базовые проверки выполнены на macOS в Obsidian 1.14.4. Плагин использует совместимые с браузером API; физические iOS/Android и минимальная версия Obsidian еще требуют проверки.

1. [Установите собранные файлы](docs/ru/installation.md) в тестовое хранилище. Одного клонирования исходников недостаточно. Установка из каталога Community требует проверки и принятия плагина Obsidian.
2. В палитре команд выполните **Noteline: Открыть временную ось**.
3. Нажмите **Добавить заметку** и выберите файл по имени или пути. Доступны также меню файла и команда добавления активной заметки.
4. Раскройте карточку отдельной кнопкой. Для редактирования исходной заметки нажмите ее название.
5. Перемещайте карточку за вертикальную ручку или кнопками **↑/↓**. Меняйте масштаб кнопками **−/+**; **Показать все** подбирает обзор выбранных дат.

[Продолжить быстрый старт](docs/ru/quick-start.md).

## Форматы заметок

Используйте существующие свойства или небольшой блок метаданных в начале заметки:

```yaml
---
timeline-date: "2026-10-22 15:30"
tags:
  - исследование
  - идеи/аудио
---
```

```markdown
📅 2026-10-22 15:30
📍 Tags: #исследование #идеи/аудио

---

Текст заметки.
```

Начальный приоритет даты: `timeline-date`, затем `date`, затем строка `📅`. Имена свойств и порядок настраиваются. Даты — календарные значения без часового пояса: запись `2026-10-22 15:30` сохраняет то же время на другом устройстве. [Форматы, конфликты и отсутствующие поля](docs/ru/dates-and-tags.md).

## Заметки и данные

Noteline хранит выбранные пути, подставленные даты и раскладку в штатном файле `data.json` плагина. Копий библиотеки заметок не создается. Открытие, раскрытие, перемещение и удаление карточки с оси не удаляют и не переписывают исходный файл. **Добавление тега — явное изменение этой заметки.**

Резервная копия должна включать заметки **и** данные плагина. При синхронизации одной оси между устройствами используйте один активный экземпляр для записи: одновременные изменения раскладки автоматически не объединяются. [Хранение и восстановление](docs/ru/data-and-security.md).

Плагин не выполняет собственных сетевых запросов, не собирает телеметрию и не требует аккаунта или сервера. Штатный Markdown-рендерер Obsidian и другие установленные плагины могут загружать внешнее содержимое, указанное в заметке.

## Разработка

Node.js 24+ и npm нужны для разработки; пользователю достаточно собранных файлов плагина.

```sh
npm ci
npm run check
npm run build
```

Production-сборка создает `main.js`. Для установки к нему нужны `manifest.json` и `styles.css`; `node_modules` в хранилище не копируется. Эти три файла прикладываются к GitHub Release отдельно, а тег должен совпадать с `manifest.version`. [Сборка и публикация](docs/ru/development.md).

## Границы версии 0.2.0

Одна ось на хранилище, одна карточка на заметку, только вертикальное размещение. Нет интервалов событий, изменения даты переносом по горизонтали, экспорта изображения, автоматического слияния конфликтов и pinch-to-zoom. Файлы, переименованные при выключенном плагине, могут потребовать ручной перепривязки. [Совместимость и ограничения](docs/ru/troubleshooting.md).
